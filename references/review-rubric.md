# 五维评审 / Review Rubric

## 输出格式

```text
哲学一致性： X/10 — [一行理由]
视觉层级：   X/10 — [一行理由]
细节执行：   X/10 — [一行理由]
功能性：     X/10 — [一行理由]
创新性：     X/10 — [一行理由]

Keep:        [做得好的]
Fix:         [必须修复，按严重度排序]
Quick wins:  [每个 ≤30 分钟]
```

## 五个维度的定义

### 哲学一致性
实现是否真正遵守了所选 philosophy 在 `design-philosophies.md` 中的**约束**？引用具体约束条目，说明满足或违反。

检查方法：逐条对照所选 philosophy 的约束清单。命中反模式即为扣分项。

### 视觉层级
每屏是否有**恰好一个**视觉焦点？新用户能否在 <2 秒内预测主操作？

检查方法：眯眼测试（模糊化后能否看出主次）；主操作是否唯一。

### 细节执行
按栈 adapter 的检查清单执行——DPI、焦点、对比度、加载/空/错误态。

检查方法：对照 adapter 的「Stack-specific review checks」逐项过。

### 功能性
界面是否**能用**：键盘、读屏、长字符串、边界数据（空、1 条、1 万条）。

检查方法：边界数据测试；键盘走一遍；长文本截断检查。

### 创新性
是否有**一个**刻意且有理据的偏离默认？零 = 安全但平淡；>1 = 噪音。

检查方法：数"刻意的非默认决策"数量，配合 justification 是否成立。

## 硬红线（机器可核对，覆盖评分）

以下任一触发，**无论维度评分如何**，评审结论强制为 **Fix**：

- 图裂 / 占位图标可见。
- 任何文本对比 < 3:1。
- 正常交互中出现控制台报错 / 堆栈。
- 控件/组件渲染出来但点击无反应。
- DPI 不匹配导致文字或图标模糊。
- 375px 视口出现无横向滚动意图的横向滚动条。
- 焦点环不可见。
- 无键盘操作路径。
- 闪烁 >3 Hz。
- 信息仅靠颜色传达。

## 各栈的额外检查项

| 栈 | 额外检查 |
|---|---|
| Python 桌面 | 100%/150%/200% DPI 缩放；系统高对比模式；信号处理器中无阻塞工作 |
| React / Vue | 375/768/1440 三档响应式；暗色模式无孤儿 hex；CLS ≤0.1 |
| Gradio / Streamlit | 首屏重组件有骨架；交互后状态不重置；移动端列折叠 |
| Textual | 256 色 / truecolor 终端兼容；快捷键覆盖 |
| 移动端 | Dynamic Type / 系统字号放大；安全区适配 |
| 数据可视化 | 色板语义正确；图例与系列顺序一致；图表有文本等价物 |

## 什么不是机器可核对的

品味判断（"好看吗""符合品牌吗"）归人。评分是**参考性**的；硬红线是**绝对**的。评分不通过不一定打回，硬红线触发一定打回。

## 与 handoff 的关系

评审报告是**完整包**的组成部分（见 `handoff.md`）。**精简包**不含三方向对比，但评审结果（尤其硬红线）仍须在改动理由中体现——缺陷修复也要过红线检查。

## 与 a11y-baseline 的关系

a11y-baseline 的硬红线（对比度、焦点、键盘、闪烁、颜色承载信息）与本文件的硬红线重合——本文件不重复定义，直接引用 `a11y-baseline.md` 的「硬红线」小节。评审时以 a11y-baseline 为准。

## 评分的使用

- **总分不用于排名**——五个维度不同质，相加无意义。
- **单维度低分**是信号，指引 Fix 的方向。
- **硬红线**是闸门，与评分独立。
- 评审报告的价值在 **Fix 清单**，不在分数本身。
