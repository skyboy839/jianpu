# 无渲染环境交付标准 / Static Deliverable

## 触发条件

当前 Agent 环境出现以下任一：
- **无截图能力**（无法渲染 UI 生成 PNG）。
- **无法执行代码**（沙盒、受限运行时）。
- **用户要求"先看草图"** 但尚未允许写代码。

触发后**必须**按本文件标准交付，不得假装有可视化。

## 交付物三件套

### 1. ASCII wireframe

- 用文本画出主要布局（ASCII / Unicode box drawing）。
- 每屏至少画出：主区域、次要区域、主操作、次要操作位置。
- 标注尺寸比例用字符数示意（如 `[=====main=====]`）。

示例：
```text
┌─────────┬───────────────────────────┐
│ Sidebar │  Header  [Search] [User]  │
│  • Inbox├───────────────────────────┤
│  • Sent │  ▢ Row 1  value  value    │
│  • Draft│  ▢ Row 2  value  value    │
└─────────┴───────────────────────────┘
```

### 2. Token table

- 完整列出 `design-spec.md` 的令牌，格式为表格。
- 每行：name / value / 用途 / 对比度检查结果（如适用）。
- light/dark 成对则两列并排。

### 3. Screenshot placeholder

- 明确标注：`[SCREENSHOT PENDING: <描述>]`。
- 说明"待渲染后补充"。
- **不得**用文字冒充视觉成果。

## 哲学可表达性矩阵（唯一权威）

本矩阵**只在此处定义**。其他文件引用时不复制。

| 哲学 | static 可表达 | 处理 |
|---|---|---|
| 信息建筑派 | 是（布局 + 密度 + 对齐） | 必须真分化 |
| 极简主义派 | 是（布局 + 留白） | 必须真分化 |
| 东方哲学派 | 部分（可表达留白与节奏，不可表达色彩温度） | 允许合并但标注"色彩待验证" |
| 运动诗学派 | 否（动效不可在 ASCII 表达） | 合并为"待渲染验证"方向 |
| 实验先锋派 | 否（视觉张力不可在 ASCII 表达） | 合并为"待渲染验证"方向 |

**最低要求**：三方向中 ≥2 个方向在布局上真分化；第三个可标注 "渲染后验证"。这对应 SKILL.md 纪律 2 的降级条款。

## Runnable / static 分级

每个 adapter 在顶部标注环境能力标签：

| 标签 | 含义 |
|---|---|
| `runnable` | 环境可执行，三方向门按"可运行产物"执行 |
| `static-only` | 环境不可执行，按本文件静态交付 |
| `capture-capable` | 环境可截图，产物含 PNG |
| `capture-disabled` | 环境不可截图，产物含 ASCII + placeholder |

Agent 加载 adapter 后立即识别标签，据此调整三方向门交付形态，但**不降低**方向数量或分化度（分化度按矩阵定义）。

## 与账本的配合

static 交付后仍须落账本——`signature` 字段用 ASCII 布局描述 + 令牌摘要代替，让下一个项目仍能对标差异。

## 与 a11y-baseline 的关系

static 交付下 a11y 检查：
- 对比度：仍可在 token 表中精确核对（色值已知）。
- 键盘：无法验证——标注"待运行时验证"。
- 动效：无法验证——标注"待运行时验证"。
- 移动触控：可核对设计规格（≥44×44 px）——在令牌表中检查。

**不得**因 static 而跳过 token 层的 a11y 检查——能核对的必须核对。
