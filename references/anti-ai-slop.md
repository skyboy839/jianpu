# 反 AI Slop 清单 / Anti-AI-Slop Checklist

## 用途

识别并拒绝"一眼 AI"的默认审美。同屏命中 ≥3 项且**无题材理由**，必须停下重做。这不是禁令清单——是**触发自我审查的信号**。

## 视觉默认（AI 输出的最大公约数）

1. **紫→蓝渐变**用作背景或按钮填充。
2. **emoji 作为主图标系统**（🚀 ✨ 🎯 撑起整个界面）。
3. **Inter（或 system-ui）作为展示字体**，在品牌/产品表面无理由使用。
4. **圆角容器 + 1px 左边框 accent 条纹**（"callout card"）。
5. **全大写灰色小标签**压在每个标题上方。
6. **`01 / 02 / 03` 编号**作为装饰性段落标签。
7. **一个衬线展示字体**，与题材无任何理由关联。
8. **玻璃拟态模糊**，无深度理由。
9. **"柔和阴影卡片 + 灰背景"重复 4 次以上**。
10. **居中 Hero + 三栏特性网格**出现在内部工具上。

## 结构性默认

11. **每屏都用同一套 12 栏网格**，不管内容类型。
12. **空状态填 lorem ipsum 或励志文案**。
13. **加载 = 仅 spinner**，从不给匹配真实布局的骨架屏。
14. **错误 = 仅红色 toast**，从无内联上下文。

## 如何为命中辩护

一个命中**允许存在**，条件是 `design-spec.md` 的 `justification` 中记录了一句理由（如"品牌使用紫渐变，依据 brand-asset-protocol §3 提取"）。**无记录理由的命中即为违规**。理由即审计线索。

## 机器可检测的信号

部分命中可被自动检查（供评审阶段使用）：

| 信号 | 检测方式 |
|---|---|
| 紫→蓝渐变 | 扫描代码中的 gradient 色值，判断色相是否落在紫-蓝区间 |
| emoji 图标 | 扫描 icon 字段 / 组件，统计 emoji 字符占比 |
| Inter 展示字体 | 扫描 `font-family` 的 display 用途声明 |
| 全大写小标签 | 扫描 `text-transform: uppercase` + 小字号 + 灰色组合 |
| 01/02/03 编号 | 正则匹配装饰性数字标签 |
| 重复卡片 | 统计同结构卡片在同一表面的出现次数 |
| lorem ipsum | 扫描占位文本 |

## 各哲学的具体反模式

`design-philosophies.md` 中每个哲学有自己的反模式（如极简主义派禁止"用灰色细分隔线填满空间"）。本文件是**跨哲学的共同底线**；各哲学的反模式在其条目内单独定义。

## 与技术栈无关

本清单**不依赖 HTML/CSS**。PyQt 窗口、React 页面、Textual TUI、Flutter 应用都适用同一套信号。检测方式因栈而异（见上表），判断标准不变。

## 与 a11y 的关系

反 slop 是**审美底线**；a11y 是**可用性底线**。两者独立：
- 一个设计可以"不 slop"但不可访问（如低对比度的精致排版）。
- 一个设计可以"可访问"但 slop（如高对比度的紫渐变卡片堆叠）。
- 两者都通过才算合格。

a11y 的加载时机见 SKILL.md（design-spec 阶段起）；本文件在所有阶段独立生效（方向门阶段即可用于筛掉 slop 方向）。
