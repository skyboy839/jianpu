# 简朴 · Jianpu

> 给 AI Agent 补上设计判断力。它是一套设计工作室的工作规范，不是样式库。

作者：曹杰（新乡君行志智能科技有限公司）

**简朴（Jianpu）** 是一个跨渲染技术的通用软件界面设计技能。它把设计工作室的工作流（约束提取、方向选择、规格制定、评审交付）翻译成 Agent 能执行的协议，覆盖 Python 桌面 / Web-UI / TUI、Node 前端 / SSR、移动端、原生桌面、声明式栈与通用栈。

它不生产样式，只做判断。

## 关于名字

**简朴**（jiǎn pǔ）——简约、质朴、去装饰。这是它的字面义。

它还有一层同音的注解：**简谱**。

简谱和五线谱记的是同一件事。五线谱完备、精确、能承载最复杂的作品，但要经过长期训练才能读写；简谱主动放弃了表达力的上限，把门槛降到业余爱好者也能照着唱出来。

这个技能取的是简谱那一侧的取舍：

| 取向  | 五线谱式             | 简谱式（本技能）         |
| --- | ---------------- | ---------------- |
| 目标  | 完备的设计系统 / 专业设计工具 | 够用、能上手的设计判断      |
| 使用者 | 专业设计师            | 非设计背景的开发者与 Agent |
| 门槛  | 学习曲线长            | 读完一遍就能执行         |

设计领域的五线谱留给 Figma 和专业设计师。它要做的是另一件事：让不会做设计决定的编码 Agent，按一套查得动、跨栈能用的规则，交出说得清理由的界面。

顺带一提：拼音 `jianpu` 在英文语境里通常正是指简谱记谱法，这层双关中英同时成立。

## 创作历程

先有的是一堆没解决的问题，名字是最后才定的。

做了十几年低代码交付，见过太多"功能跑通了、界面没法看"的项目（包括我自己的项目）。后来 AI 写代码普及，问题没消失，只是换了形态：Agent 能写，但不会做判断：不知道该先给你三个方向挑，不知道紫渐变是 AI 味，改个色值也不会顺手去查对比度,总而言之就一个字：太烂！

起点是读到 [huashu-design](https://cnb.cool/huashu-2026/huashu-design)（MIT）。它把"反 AI slop""品牌资产五步"这些事写成了能照着做的 spec，我先在自己的项目里用。没多久就撞到边界：它面向 HTML 产出物，而我的项目是 PyQt、Textual、Electron——那些规则一到桌面和 TUI 里就松掉。Claude Design 也试过，卡在同一个地方：它给你一张画布，我要的是能交给编码 Agent 执行的规格。

于是有了这份 spec 的主体：把判断从单一栈里抽出来，做成跨渲染层的协议，补上栈路由、三层令牌、豁免门、外观账本和交付包。借鉴的部分写在致谢里，多出来的那层才是正文。

## 这是什么

多数设计技能管的是"生成一个好看的界面"。简朴往上游走一步，管的是判断本身：

- 方向：三方向门强制给三个哲学不同的真实选项，选一个再动手。
- 验收：五维评审 + 硬红线 + 豁免门证据，做得好不好要能核对，不靠感觉。
- 反 slop：清单加辩护机制，同屏命中三项又说不出题材理由，就重做。
- 跨栈：8 个栈适配器 + 路由判定 + 声明式映射 + 三层令牌，同一套决策换个栈也成立。

所以它是一套设计判断流程，不是样式模板。前提是 Agent 已经会写代码，缺的只是"像设计师那样做决定"的方法。

## 为什么需要它

AI 做界面，卡住的地方很少是 CSS。反复出现的是这五件事：

1. **上来就做，不做选择。** 没有方向可挑，直接给一个方案。（痛）
2. **默认审美泛滥。** 紫渐变、emoji 图标、满屏 Inter、01/02/03 编号。（很痛）
3. **无法解释为什么。** 做了，但说不清为什么这样做、为什么不那样做。（太痛了）
4. **跨栈失效。** 在 React 里奏效的判断，到 PyQt 或 TUI 里不会迁移。（真实踩坑）
5. **改一处炸一片。** 没有令牌分层，颜色和间距散落各处。（我也要炸了）

这五件事各有一条硬规则对应。简朴要的不是界面更好看，是设计过程能被追溯、被评审，换栈还能复用。

## 核心特色

### 🚪 三方向门

任何新视觉设计任务，必须先呈现三个**真正不同**的真实产物，用户选一个再执行。（**别信自己能一次过**）

- 三个方向必须在**设计哲学**上不同，不是配色变体。
- 产物必须是真实可运行/可静态呈现的最小界面，不是文字描述。
- 用户指名风格也不能豁免。（**切肤之痛**）
- 从零设计三个全不同；存量改造允许一个是"现有哲学增强"。（没办法，我总不能造两个给你）

### 🎨 设计哲学库

5 个流派 × 20 种设计哲学，每种以**约束 + 反模式 + 最适合**书写，技术无关：

| 流派    | 代表哲学                  | 气质         |
| ----- | --------------------- | ---------- |
| 信息建筑派 | 信息建筑、数据仪表、编辑网格、技术控制台  | 理性、数据驱动、克制 |
| 运动诗学派 | 运动诗学、实时反馈、游戏化动效、生成式动效 | 动感、沉浸、技术美学 |
| 极简主义派 | 极简主义、瑞士网格、静奢、单功能      | 秩序、留白、精致   |
| 实验先锋派 | 粗野主义、新孟菲斯、生成艺术、故障美学   | 先锋、冲击、实验   |
| 东方哲学派 | 东方哲学、禅意留白、水墨、文雅静谧     | 温润、诗意、安静   |

### 🚫 反 AI Slop

识别并拒绝"一眼 AI"的默认审美。同屏命中 ≥3 项且无题材理由 → 停下重做：

紫→蓝渐变 · emoji 图标 · 满屏 Inter · 圆角+左边框 accent · 全大写灰标签 · 01/02/03 编号 · 无故衬线展示字体 · 玻璃拟态 · 卡片堆叠 · 居中 Hero 三栏

### 🛡️ 豁免门

不是所有改动都需要三方向门。豁免门用**三问 + 证据**做结构化判定：

1. 是否涉及布局骨架？
2. 是否新增哲学层面的视觉决策？
3. 是否改变现有令牌或组件契约？

三问全"否"才豁免，每问必须附机器可核对的证据（**这一点你别替AI做决定**）。防止"小改动被流程淹没"或"大改动绕过流程"两个极端。

### 📐 设计规格先行

先产出技术中立的 `design-spec.md`（色板、字号、间距、圆角、动效缓动），再映射到目标栈的令牌。色板强制 light/dark 成对，对比度显式断言。

### 🧱 令牌三层

所有令牌分三层，组件只引用语义层，绝不直接引用原语层：

```text
Primitive（原语层）  →  oklch(0.62 0.16 250), 16px
Semantic（语义层）   →  color.text.primary = primitive.blue.900
Component（组件层）  →  button.primary.bg = semantic.action.primary
```

改原语只影响颜色本身；改语义影响所有引用方。这是版本化的风险分界。

### 🤝 交付包

多 Agent 协作时，唯一接口是"设计交付包"，按任务类型定义最小集：

- **完整包**（全新设计 / restyle）：design-spec + tokens + 三方向对比 + 评审报告 + 账本条目。
- **精简包**（豁免门任务）：前后截图 + 四字段结构化理由 + token 差异。

### ♿ 可访问性基线

前置基线，不是可选章节。对比度、键盘、焦点、动效、暗色、触控目标各有硬红线。各行业 profile（医疗、政务、教育、HMI）在其上只做加法。

### 📄 静态环境降级

无截图、无法执行代码的环境，按《哲学可表达性矩阵》降级为 ASCII wireframe + 令牌表 + 截图占位。布局类哲学必须真分化，动效类哲学可以合并，标一句"待渲染验证"。

## 快速开始

### 最小使用（单人 / 单一界面 / 非多端）

只加载 5 个文件：

```text
SKILL.md
+ references/three-directions-gate.md
+ references/design-philosophies.md
+ references/anti-ai-slop.md
+ references/review-rubric.md
```

这五个文件覆盖从零设计或存量优化的完整流程：约束提取 → 选三方向 → 方向门 → 规格 → 评审。

### 完整使用

Agent 根据工作区信号自动路由到对应适配器，按任务类型加载跨任务基础层。完整加载策略见 `SKILL.md` 的「栈路由」和「跨任务基础层」表。

### 触发方式

在 Agent 对话中说：

- "设计一个倒计时工具"
- "优化我的仪表盘"
- "这个登录页对比度有问题，帮我改一下"
- "评审我的 UI"

只要任务面向用户可见界面（UI、屏幕、视图、交互面），就会触发本技能。纯后端逻辑、API 设计、数据库 schema、部署不触发。

## 核心概念

### direction-proposal vs design-spec

| 阶段  | 产物                        | 模式            | a11y 义务 |
| --- | ------------------------- | ------------- | ------- |
| 方向门 | direction-proposal（3 个候选） | 只出 light      | 无       |
| 选定后 | design-spec（1 个规格）        | light/dark 成对 | 完整检查    |

三方向门只出 1 套 light，不承担 light/dark 成本；方向选定后才补齐成对色板。这是阶段分离，跟偷工减料无关。

### philosophy key vs movement

- **movement**：5 个流派（信息建筑 / 极简 / 运动诗学 / 实验先锋 / 东方）。
- **philosophy key**：20 种哲学的唯一键（如 `minimalism`）。

"不同方向"的比较单位是 **philosophy key**，不是 movement。同属理性系的信息建筑与极简主义，key 不同，算不同方向。

### 三层令牌与品牌锁定

`brand_locked` 锁定的是 **primitive 层的具体色值**（如 accent 的 OKLCH），不锁 semantic 层的映射。semantic 可自由映射到已锁定或未锁定的 primitive，设计自由度还在，品牌约束也没破。

### 五维评审

哲学一致性 · 视觉层级 · 细节执行 · 功能性 · 创新性，各 0–10 分。**评分只是参考，硬红线不打折。** 图裂、对比度不足、焦点环不可见、无键盘路径，命中任何一条直接 Fix，不看分数。

## 工作流示例

一个典型的从零设计任务（PyQt 倒计时工具）：

```text
1. 路由 → python-desktop.md
2. 约束提取 → 硬约束：PyQt5、无外部图标字体；软约束：偏好浅色
3. 选择启发式 → 用户说"简单/工具" → 极简主义 + 信息建筑 + 东方哲学
4. 三方向门 → 三个可运行窗口截图，用户选极简主义
5. design-spec → 成对 light/dark 色板 + 96pt 等宽数字 + 2 个主动元素
6. 令牌三层 → primitives.py / semantic.py / components.py
7. 实现 → 布局骨架 → 视觉 → 交互 → a11y 检查
8. 五维评审 → 8/9/7/8/6，无硬红线
9. 落账本 → 下一项目必须与"96pt 单色等宽数字"差异化
```

一个典型的豁免门任务（React 登录页对比度修复）：

```text
1. 路由 → node-react.md
2. 豁免门三问 → 布局？否。哲学决策？否。令牌契约？否（仅改映射值）。
3. 证据 → diff 仅色值，无结构变化
4. a11y 校验 → blue.600 对白底 7.2:1，满足 AA
5. 精简包 → before/after PNG + 四字段理由（含排除项）+ token diff
6. 不引用账本（纯缺陷修复）
```

## 完整案例

下面是一个走完全程的例子：给 on-call 工程师的终端监控面板，Python + Textual，必须在 SSH 里能跑。

这类约束 GUI 工具和 HTML 生成器都不处理：它们给你画布或页面，而终端只有字符网格、16 色降级和网络延迟。

### 约束提取

- 硬：无图形无鼠标；需要 256 色降级路径；SSH 有延迟。
- 软：团队习惯暗色；已有 Textual 2.x 依赖。

用户原话是"简单点，看一眼就知道有没有事"。关键词映射出三个候选：`technical-console`、`data-dashboard`、`minimalism`。

### 三方向门

三个方向都跑得起来，同一份 mock 数据，同一终端尺寸 120×36：

| 方向                  | 形态                             | 差异点                        |
| ------------------- | ------------------------------ | -------------------------- |
| `technical-console` | 等宽数据表 + 可滚动日志 + 常驻快捷键栏         | 日志做主栏，信息密度最高；状态用文本 + 符号双编码 |
| `data-dashboard`    | 6 张指标卡（各 1 关键值 + 1 上下文）+ 刷新时间戳 | 以卡片为组织单位，日志退到二级            |
| `minimalism`        | 一个大号健康度 + 三个无框数字               | 首屏主动元素 ≤5，留白过半             |

用户选了 `technical-console`，理由很实际：出事了第一件事是翻日志，另外两个方向都把日志推到了二级页面。

### design-spec 片段

色板部分，对比度是实测值，不是估的：

```yaml
philosophy: technical-console
movement: information
subject: "on-call 运维面板（Textual TUI，SSH 环境）"

justification:
  - "日志是主栏：出事后第一诉求是查日志"
  - "状态用文本 + 符号双编码，不靠颜色单打"
  - "无装饰图标：终端里图标的识别成本高于文字"

constraints:
  hard: ["无图形无鼠标", "需要 256 色降级路径"]
  soft: ["团队习惯暗色", "复用现有 Textual 2.x"]

colors:
  bg:
    light: oklch(0.975 0.004 250)   # #F5F7F9
    dark:  oklch(0.18 0.010 250)    # #0E1216
  surface:
    light: oklch(0.945 0.007 250)   # #E9EDF1
    dark:  oklch(0.24 0.012 250)    # #1B2025
  text:
    light: oklch(0.22 0.012 250)    # #161B20  16.10:1 vs bg
    dark:  oklch(0.93 0.010 250)    # #E3E8EE  15.31:1 vs bg
  muted:
    light: oklch(0.51 0.014 250)    # #60676E  5.34:1
    dark:  oklch(0.64 0.015 250)    # #868D95  5.60:1
  accent:
    light: oklch(0.52 0.112 195)    # #007C7D  4.69:1
    dark:  oklch(0.74 0.150 195)    # #00C7C8  8.94:1
  danger:
    light: oklch(0.52 0.180 25)     # #BA2B2E  5.63:1
    dark:  oklch(0.70 0.190 25)     # #FF645F  6.46:1
  success:
    light: oklch(0.49 0.120 150)    # #1D7339  5.51:1
    dark:  oklch(0.76 0.150 150)    # #61CB7C  9.28:1
  warning:
    light: oklch(0.48 0.110 80)     # #7E5500  6.16:1
    dark:  oklch(0.82 0.140 85)     # #EEBC4A  10.68:1

a11y:
  wcag_level: AA          # 正文以 14px 等宽为主取 AA；关键数值另按 AAA
  dark_mode: paired
```

初版 light accent 是 `oklch(0.53 0.115 195)`，实测 4.48:1，差 0.02 不达标；压到 `0.52 0.112` 后 4.69:1 通过。这种差距眼睛看不出来，只能算。

### 令牌三层 → Textual

```python
# primitives.py —— 只放原始色，组件不许引用
PRIMITIVE = {
    "bg":      ("#F5F7F9", "#0E1216"),
    "surface": ("#E9EDF1", "#1B2025"),
    "text":    ("#161B20", "#E3E8EE"),
    "muted":   ("#60676E", "#868D95"),
    "accent":  ("#007C7D", "#00C7C8"),
    "danger":  ("#BA2B2E", "#FF645F"),
    "success": ("#1D7339", "#61CB7C"),
    "warning": ("#7E5500", "#EEBC4A"),
}

# semantic.py —— 语义层，组件只认这里
SEMANTIC = {
    "screen.bg":    "bg",
    "panel.bg":     "surface",
    "log.text":     "text",
    "log.time":     "muted",
    "status.ok":    "success",
    "status.warn":  "warning",
    "status.crit":  "danger",
    "focus.border": "accent",
}
```

改 `warning` 的原始色，只有语义层引用它的地方会变；改 `log.time` 的映射，只影响时间戳。这就是三层令牌划出的风险边界。

### 评审与复盘

五维评分：哲学一致性 9、视觉层级 8、细节执行 8、功能性 9、创新性 5。创新性低是故意的——运维面板不需要新鲜感。

硬红线全过：焦点环用 `accent`，8.94:1 可见；状态不只靠颜色，带 `[OK]` / `[!!]` / `[XX]` 文本前缀；全键盘可操作；256 色降级下色相有偏移，但对比度靠 ANSI 16 色映射守住（单独存 `ansi_fallback.py`）。

账本记一条：`technical-console` + 等宽双编码 + 日志主栏 → 本工作区下一个面板任务不能再沿用这套组织方式。

## 设计原则

简朴自己守同样的原则：

1. **单点定义，其余引用。** 每条规则只在唯一权威文件里写一次，别处只引用，避免分叉。
2. **可验证优于可描述。** 规则尽量附带机器能核对的证据（对比度数值、diff、签名变化），不靠"我觉得"。
3. **降级不降标准。** 没有渲染环境就降成 ASCII，但方向数量、分化度、token 层的 a11y 检查一样不少。
4. **阶段性加载。** 不默认加载全部 17 个 references，按任务类型和阶段取，省上下文。
5. **诚实边界。** 只治理用户看到和操作的那一层。后端逻辑、API 架构、数据库设计不在职责内。

## 常见问题

**Q：它和别的"设计技能"有什么区别？**

多数设计技能扣在某个技术栈或某套风格模板上，给你的是"长什么样"。简朴回答的是另一类问题：方向怎么挑、规格怎么写、评审怎么判、换个栈怎么落地。交出来的是流程，不是样式。

**Q：适合什么场景？**

从零设计、存量优化、设计系统建设、多端一致性、竞品对标、UI 缺陷修复（豁免门）、无渲染环境设计（静态降级）。

**Q：不适合什么场景？**

纯后端逻辑、API 设计、数据库 schema、部署架构。这些不在设计技能的职责内。

**Q：单人项目用全套会不会太重？**

用「最小使用」路径（5 个文件）即可。治理层文件（handoff、ledger、brand 协议）只在需要时加载。

**Q：三方向门会不会拖慢流程？**

对真正的小改动（纯色值调整、保外观的 bug fix），豁免门会放行。三方向门只对"产出新视觉设计"的任务触发，这类任务本来就得先定方向。

**Q：支持中文界面吗？**

支持。CJK 宽度、字体回退、行高调整在 `python-tui.md` 和 `a11y-baseline.md` 中有专门约束。

**Q：品牌资产怎么处理？**

五步协议：问 → 官方渠道 → 下载资产 → 频率排序提取 → 固化 `brand-spec.md`。不许凭 Agent 的记忆猜。用户口述的色值可以采纳，但要标成低信任，不进 brand_locked。
